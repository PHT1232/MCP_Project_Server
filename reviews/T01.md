## Findings

### Follow-ups (assign downstream)
- **S-T06** — `add_focus`/`update_focus`/`resolve_focus` exist **alongside** `set_current_focus`. Documented (`set_*` replaces, `add_focus` appends), and defensible for FR2's "task(s)", but T06 must decide which the dashboard shows/edits. Consider dropping the generic focus CRUD if the frontend only needs replace-semantics.
- **N4 / T09** — the S2 test proves the wrapper *calls* `log_tool_call` and that `JsonFormatter` renders correctly, but not the two together through the real logger. T09 should add: `configure_logging()` + a capturing handler on the `pcs` logger + assert one parseable JSON line per tool call.

### Nits (non-blocking)
- **N1** — `assembly._render_section` has a dead `if section == SECTION_REQUIREMENTS` branch inside the generic loop (requirements are handled by an earlier `return _render_requirements(...)`).
- **N2** — `service._status_line` uses string literals `"blockers"`/`"bugs"` instead of the `SECTION_*` constants.
- **N3** — `related_entry_id` has no FK (just `String(36)`); `_assert_related` validates at write time only. Harmless (entries are only soft-deleted) — a real FK or a periodic check would be tidier.
- **N5** — duplicate `_project_json` (routes.py) / `_project_dict` (tools.py); fold into `service` or `types`.
- **N6** — `ContextEntry.updated_at` dropped `onupdate=func.now()` (service sets it manually everywhere) while `Project.updated_at` keeps it — inconsistent, not wrong.
- **N7 / T09 perf** — `get_project_briefing` loads all non-deleted rows into Python and filters resolved/expired there; no composite `(project_id, section, status)` index. Fine for a typical project (NFR1), revisit for scale.
