## B1 (blocker) — container binds loopback; published port is dead

`bind_mode=localhost` → the server binds **`127.0.0.1:8080` inside the container**
(`Uvicorn running on http://127.0.0.1:8080`, `/proc/net/tcp` shows `0100007F:1F90`
only). Docker's `ports: "127.0.0.1:8080:8080"` forwards the host loopback to the
**container's bridge IP**, not container loopback — so:

- `curl http://127.0.0.1:8080/api/health` **from the host → connection refused** (`000`).
- The compose healthcheck still passes because it runs *inside* the container
  hitting `127.0.0.1` directly, so `docker compose up --wait` reports **healthy**
  while the stack is unusable.
- **AC25 fails**: from a clean checkout you cannot register a project or fetch a
  briefing.

The handoff frames "never bind `0.0.0.0`" as the security property, but in a
container that's wrong: the security boundary for NFR14 is the **host-side
publish** (`127.0.0.1:8080:8080` — already correct), not the in-container bind.
A process on the container's internal interface is not LAN/public-exposed.

**Fix:** give the container an explicit bind override and set it to `0.0.0.0` in
`deploy/docker-compose.yml` (server service only), e.g. a `PCS_BIND_HOST` /
`PCS_HTTP_HOST` env var consumed by `bind_host()` that:
- when set, is used verbatim **only if** it is a wildcard *or* an address the
  process can bind (keep the loopback-in-tailscale-mode guard);
- is documented as "container-internal; the compose `ports:` mapping is what keeps
  it loopback-only on the host".

The Tailscale overlay path is fine as-is (server joins the sidecar netns and
binds the real tailnet interface, no publish) — don't change that.

**Retest before re-review:** `PCS_IMAGE=… docker compose -f deploy/docker-compose.yml up -d --wait`
then `curl -sf http://127.0.0.1:8080/api/health` from the host, register a project
with `root_path=/repos`, fetch its briefing. Add a test that asserts the compose
server service sets the container bind to a non-loopback address.

## Should-fix (same branch, with B1)

- **S1 — no `git` in the runtime image.** `deploy/Dockerfile.server` runtime
  stage is `python:3.12-slim` with no `git`; `docker … exec server command -v git`
  → not found. T03's `pcs.index.gitutil` shells out to `git` — without it,
  incremental reindex silently degrades to a full walk every time and blobs are
  never recorded. `apt-get install -y --no-install-recommends git` in the runtime
  stage. (Flagged in reviews/T03.md notes for T08.)
- **S2 — `resolve_tailscale_ipv4` doesn't validate the Tailscale range.** It
  rejects wildcards and loopback but would happily bind a LAN IP (e.g. a typo in
  `PCS_TAILSCALE_IP=192.168.1.5`, or a mis-named `tailscale0`). NFR14 says "never
  a LAN interface". Require the resolved address to be in `100.64.0.0/10`
  (Tailscale CGNAT) — or at least reject non-private ranges — and test it.
- **S3 — `bind_host` recomputes (and shells out) on every access.** `_health`
  route returns `settings.bind_host`; `healthcheck.py` reads it. In
  `bind_mode=tailscale` every `/api/health` call spawns `tailscale ip -4`. Cache
  the resolved address (memoize `resolve_tailscale_ipv4`, or resolve once in
  `pcs http` and stash it).
- **S4 — `repos/` is committed and not ignored.** The README tells users to
  `git checkout` into `repos/`, and T02 will write `repos/.project-context/…`.
  Add `repos/*` to `.gitignore` with `!repos/README.md` /
  `!repos/.project-context/README.md` so a user's checked-out repo and generated
  requirements file don't pollute this repo's tree.
